\chapter{Ramas de entrenamiento y de servicios}
\label{ap:ramas}

Este apéndice reúne las otras ramas. En cada una figuran el commit, los comandos de instalación y de evaluación, y el SHA-256 de los pesos usados. El detalle de directorios queda en el \texttt{README} de cada una.

\section{\textit{scratch-mediapipe-v3}: Repositorio de entrenamiento del clasificador}
Este repositorio entrena y evalúa el clasificador de señas aisladas. Vive en la rama \texttt{scratch-mediapipe-v3}. El archivo de pesos que sale de ese entrenamiento es el que después carga el motor local.

Todo el código está en \texttt{src/}. \texttt{train.py} ajusta el modelo y guarda el peso, \texttt{tune\_\allowbreak optuna.py} busca hiperparámetros, y \texttt{preprocessing.py} convierte los videos MP4 en coordenadas. \texttt{camera.py} mide el acierto frente a la cámara. La arquitectura está en \texttt{model\_arch.py}. \texttt{config.py} fija las rutas, las 100 clases y la ventana de 16 fotogramas. La extracción usa el Holistic del navegador, el mismo paquete que la extensión, a través de \texttt{holistic\_web.py}. Los videos quedan en \texttt{dataset/} y las coordenadas en \texttt{dataset\_\allowbreak landmarks\_\allowbreak 16frames/}. Los pesos y los registros salen a \texttt{src/\allowbreak model\_\allowbreak new\_\allowbreak 2026\_\allowbreak 10\_\allowbreak 20/}, con el checkpoint \texttt{tinyskeleton\_\allowbreak best.pth}.

El commit de la rama es \url{https://github.com/FranciscoVeronING/2026_Proyecto_LSA/commit/af16107261a2627de46fb125933bb02768c78eb0}. La instalación parte de la raíz. El entrenamiento y la evaluación parten de \texttt{src/}.

\begin{lstlisting}
conda env create -f environment.yml
conda activate lsa_gpu
cd src/holistic_web
npm install
npx playwright install chromium
cd ..
python check_env.py
python train.py
python camera.py --eval
\end{lstlisting}

El checkpoint de esa evaluación es \texttt{tinyskeleton\_best.pth}. Está en el commit. Su SHA-256 es

{\ttfamily\small 6ac921623778b17c186c13f0165eee05\allowbreak 80950e4c336ed625e8a30fdf090d8a5b}.

El motor local carga ese mismo archivo.

\section{\textit{semantic-cloud}: Servicio semántico en la nube}
Este repositorio es el servicio que el motor local consulta para traducir. Atiende las dos direcciones, de glosas hacia español y de español hacia glosas, con los binarios que entregan los repositorios de entrenamiento. Su tarea es responder un enunciado ya armado, y no forma parte de lo que se instala en la computadora de quien llama.

El arranque está en \texttt{run\_semantic\_server.py}. El servicio vive en \texttt{src/semantic/}: \texttt{api.py} expone las rutas, \texttt{service.py} separa los dos canales y \texttt{engine.py} ejecuta el binario. Los pesos no comparten carpeta. \texttt{models/sign/} guarda el canal de glosas hacia español y \texttt{models/hearing/} el canal inverso. En cada una hay un binario principal, un respaldo y el \texttt{sys\_prompt.txt} de esa dirección.

El commit de la rama es \url{https://github.com/FranciscoVeronING/2026_Proyecto_LSA/commit/d5bf916c55aab805338f6621b7de592b988dc0ce}. La instalación y la prueba local parten de la raíz. Git no versiona los \texttt{.gguf}. Los archivos finales de los dos canales están en \url{https://huggingface.co/maite123/lsa-semantic-gguf}. El canal directo ocupa \texttt{sordo/} y el inverso, \texttt{oyente/}. El SHA-256 de Hugging Face coincide con el de cada archivo de abajo.

\begin{lstlisting}
pip install -r requirements.txt
python run_semantic_server.py
curl -s http://127.0.0.1:8787/health
curl -s -X POST http://127.0.0.1:8787/sign -H "Content-Type: application/json" -d "{\"glosses\":\"HOLA\"}"
curl -s -X POST http://127.0.0.1:8787/hearing -H "Content-Type: application/json" -d "{\"spanish\":\"Hola\"}"
\end{lstlisting}

\section{\textit{semantic-v2}: Entrenamiento del canal directo}
Este repositorio ajusta y evalúa los modelos que pasan de glosas a una oración en español. El binario que resulta de ese entrenamiento es el que después carga el servicio en la nube para el canal directo.

Todo el código está en \texttt{src/semantic/}. \texttt{train.py} ajusta un modelo y exporta el binario, \texttt{eval\_trial.py} lo compara sobre oraciones fuera del corte, y \texttt{models.py} es el catálogo: sumar una familia es agregar una entrada ahí. El corpus está en \texttt{dataset\_glosses.json}, las oraciones de prueba en \texttt{dataset\_trial.json} y las instrucciones del modelo en \texttt{prompts/sys\_prompt.txt}. Los pesos y los registros salen a \texttt{outputs/}. Cada familia se identifica con un id estable, como \texttt{qwen2.5-1.5b} o \texttt{llama-3.2-1b}, y ese mismo id nombra su carpeta de salida.

\section{\textit{avatar-cloud}: Servicio de poses del avatar}
Este repositorio publica los archivos de pose que el motor local pide para dibujar el avatar. No entrena modelos ni traduce texto. El cliente de la videollamada solicita esas poses a este servicio.

El código cabe en \texttt{app/}: \texttt{main.py} arranca el servicio, \texttt{config.py} fija rutas y tipos de archivo, y \texttt{fingerspell.py} resuelve el alfabeto manual. Las poses están en \texttt{poses/}. El servidor devuelve el archivo cuyo nombre coincide con el pedido. Ese nombre, sin extensión, va en mayúsculas y en ASCII: sin tildes y sin eñe.

Al armar el pedido, ILSA transforma la "ñ" en "n": \texttt{MAÑANA} busca \texttt{MANANA.pose}. La letra Ñ, cuando es la glosa entera, se pide como \texttt{ENIE}. Antes del subtítulo, ILSA restituye la Ñ.

Una etiqueta compuesta tampoco es el nombre del archivo. El clasificador reescribe \texttt{hermano\_a} como \texttt{HERMANO}, \texttt{esposo\_a} como \texttt{ESPOSO} y \texttt{hijo\_a} como \texttt{HIJO}: el sufijo \texttt{\_a} marca el género y no entra al archivo. \texttt{vivir\_en} se reescribe como \texttt{VIVIR\_EN}. Al pedir la pose, ILSA borra los guiones bajos, así \texttt{VIVIR\_EN} busca \texttt{VIVIREN.pose}.

El commit de la rama es \url{https://github.com/FranciscoVeronING/2026_Proyecto_LSA/commit/a713860b071bceacb2e7b1ed4145ecd1a73f0b55}. Esta rama no entrena un modelo y no tiene archivo de pesos. Los comandos parten de la raíz. La comprobación es \texttt{GET /health} y un \texttt{GET /tposes/\{glosa\}.pose} en el puerto 8080.

\begin{lstlisting}
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python -m app.main
\end{lstlisting}
